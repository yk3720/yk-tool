Node.js をマップする

サーバー上で動く JavaScript と、その周辺の考え方

ひとことで言えば

まずここだけ押さえる

Node.js（ノード・ジェイエス）は、ブラウザ外で JavaScript を実行するためのランタイム環境である。エンジンは Chrome と同じ V8（ブイエイト）を使う。

対象読者は、プログラミング基礎と HTTP のざっくりしたイメージを持つ理系エンジニア。カバー範囲は「サーバー・CLI・ビルドツールの土台」まで。フレームワーク固有の話は別マップに譲る。

V8（ブイエイト）とは？

Google が開発した JavaScript エンジン。ソースを機械語に近い形へ JIT コンパイルして高速実行する。Node はこのエンジンを「ブラウザの外」に持ち出し、ファイル I/O やソケットなど OS 機能と結び付けた。

なぜ Node.js は生まれたのか？

2000年代後半、Web のフロントは JavaScript、サーバーは別言語という二重の言語スタックが普通だった。Ajax 以降、リアルタイム性や同時接続の扱いが重くなり、「同じ言語で I/O 多めのサーバーを書けないか」という動機が強まった。

Node は イベント駆動・ノンブロッキング I/O を前面に出し、1 プロセスあたりのスレッド数を抑えつつ大量の接続をさばく設計を選んだ。解決したかった課題は「C10k 問題に近い同時接続」と「フロントとバックの言語分裂」の両方である。

まず理解する3つ

ここが腹落ちすれば、メモの内容は自分の言葉に置き換えられる。

  1. 1

    非同期イベント駆動

    I/O 完了を「待ち続けて CPU を占有しない」。イベント（コールバック・Promise など）で次の処理に進む。チャットや SSE、WebSocket 的な多接続・待ち時間多めに強い。

  2. 2

    シングルスレッドとイベントループ

    JavaScript 実行は基本 1 本のメインスレッド上。タイマー・I/O 完了・マイクロタスクのキューを回すのがイベントループ。重い CPU 計算はメインスレッドを塞ぐので別戦略が要る。

  3. 3

    npm（エヌピーエム）

    Node Package Manager（ノード・パッケージ・マネージャ）。公開パッケージのレジストリと CLI で、依存関係を宣言的に取り込む。フロントのビルドチェーンもここから組むことが多い。

主要概念とアーキテクチャ

API（Application Programming Interface：アプリケーション プログラミング インタフェース）

ここでは「HTTP で JSON を返すサーバー」など、プログラム同士が契約として共有するインタフェースの意味。Node は Express や Fastify などで HTTP API を組み立てる典型例が多い。

ざっくりデータの流れ（概念図）

クライアント → OS / libuv → イベントキュー → V8（JS 実行） → レスポンス

libuv（リブユーブイ）は、非同期 I/O とスレッドプールなどを担う C ライブラリ。メモの「シングルスレッド」と「効率的な I/O」の橋渡しをする層である。

たとえ話（構造の対応を意識する）

非同期 I/O とレストランのウェイター

ウェイターが一品の調理完了までキッチン前で立ち尽くさず、注文を渡したら他のテーブルに戻る。料理が上がったら「ピックアップ」で対応する。これがノンブロッキング I/O に近い。対応関係：ウェイター＝メインスレッド、キッチン＝OS／ディスク／ネットワーク、ピックアップ＝コールバック／Promise の解決。

イベントループと回転寿司のレーン

1 本のレーン（メインスレッド）に皿（タスク）が流れてくる。客（ランタイム）は順に取り分けるが、長時間かかる皿（CPU 重い同期処理）はレーン全体を詰まらせる。対応：重い処理は Worker スレッドや別プロセスに逃がす設計が必要になる。

npm と部品カタログ＋物流

package.json が BOM に相当し、node_modules が現場に届いた部品置き場。バージョン範囲とロックファイル（例：package-lock）で再現性を担保する、という見方が実務では効く。

メモにあった「活用シーン」を位置づける

  • Web サーバー・API：HTTP サーバーとして JSON を返す、BFF（Backend for Frontend）など。
  • フロントのビルド：React / Vue などのトランスパイル・バンドルは Node 上の CLI が標準。
  • IoT：リソース制約デバイスではなく、ゲートウェイや開発用ホストで Node を使う例が多い（現場では制約に応じて他言語も検討）。

コード例

次のコードは、HTTP で「Hello」を返す最小のサーバーを起動する。リクエストごとにコールバックが呼ばれ、ブロックせずに次の接続を受け付けられる。

// Node に組み込みの http モジュールを使う
const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' });
  res.end('Hello from Node.js\n');
});

server.listen(3000, () => {
  console.log('listening on http://localhost:3000');
});

初心者がはまりやすい落とし穴

  • CPU バウンドをメインスレッドで回す：画像の大量リサイズや巨大 JSON の同期パースでイベントループが止まり、全体の応答性が死ぬ。Worker、別サービス、ネイティブ拡張などで逃がす。
  • コールバック地獄とエラー処理の漏れ：古いスタイルの入れ子は読みにくい。async/await と try/catch、または Promise の .catch で統一する習慣が安全。
  • npm 依存の供給連鎖：パッケージ数が爆発し脆弱性や悪意あるスクリプトのリスクが増える。ロックファイルのコミット、監査（npm audit）、必要最小限の依存を心がける。

専門用語集

ランタイム（runtime）
プログラムを実行するための土台（VM・標準 API・イベントループなどの総体）。
イベントループ（event loop）
コールバックやマイクロタスクを順に消化し、I/O 完了と JS 実行を接続する仕組み。→ 「まず理解する3つ」の項参照。
ノンブロッキング I/O（non-blocking I/O）
ディスクやネットの待ちでスレッドを占有しない I/O モデル。完了は後から通知される。
libuv
Node が内部で使う非同期 I/O ライブラリ。タイマーやファイル、ネットワークの抽象化を担う。
CommonJS / ES Modules
JavaScript のモジュール形式。Node は歴史的に require が主流で、現行は import も設定により利用可能。
npx（エヌピーエックス）
ローカルまたは一時的にパッケージの CLI を実行するための npm に付属のコマンド。

次に学ぶと良いもの

  • Express / Fastify：HTTP API を現実的な規模で組むためのフレームワーク。
  • TypeScript + Node：型で契約を明示し、大規模化しやすくする。
  • ストリームとバックプレッシャ：大きなペイロードをメモリ効率よく扱う Node 固有の強み。
