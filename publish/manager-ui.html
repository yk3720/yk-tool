POINT 2

ツールで解決する課題

図解を作るほど、「あの図解どこだっけ」が増える

surge.sh にデプロイした図解が増えると、URLや台帳を追うのが追いつかなくなる。主用途は探して見返す。共有はその次。

Before
  • ·ブックマークや台帳を横断して探す
  • ·タイトルをうろ覚えだと辿り着けない
  • ·Techmap と CuriosityMap が混ざる
After
  • ·種別 → トピック → 検索／タグで段階的に絞る
  • ·カードで候補を一覧比較できる
  • ·詳細で確認してから1クリックで開く

出典: 設計メモ（grill-me）・ Master-detail UX Pattern

POINT 3

工夫したポイント

1

段階的な絞り込み（種別 → トピック → 検索／タグ）

いきなり全文検索だけに頼らない。まず「どの棚か」を決め、次にトピック、必要ならタグやキーワードで細かくする。タイトルを忘れても辿れる。

サイドバー2階層 タグクラウド NFKC正規化検索
2

「確認してから開く」マスター詳細

カードをクリックしてもすぐ外部タブは開かない。右ペインでタイトル・タグ・メモを見てから「図解を開く」。誤クリックで迷子にならない。

出典: Workspace pattern（複数ビューを同居） · Master-detail

3

見た目だけ削る機能フラグ（拡張前提）

削除やメモ編集は今月は出さないが、型・純関数・ハンドラの枠は残す。フラグOFFのときは「押せるが何もしない」ボタンを置かず、描画自体をスキップする。

POINT 4

苦戦したポイント

いちばんの曲がり角は、第5回で描いた4ペインを、そのまま作れなかったことです。

当初案：4ペイン
種別
一覧
詳細
プレビュー

右端に surge を iframe で埋め込む想定だったが、細部が見えず全画面が必要な図解では実用にならなかった。

採用：3ペイン
種別
一覧
詳細→開く

プレビューを捨て、「一覧で選ぶ → 詳細で確認 → 外部タブで開く」に集約。画面の役割がはっきりした。

検討して見送ったもの

直接URLを開く 中身を見る前に飛んでしまうため不採用
種別の横タブ 種別が増えると並びきらない → 縦サイドバー
サムネイル必須 カードが重くなる。タイトル＋タグ＋メモで識別

ひとことで言うと

図解の「倉庫番」ではなく、探して見返すための3ペイン画面。 最初の4ペイン案を捨てたことが、かえって目的をクリアにした。
