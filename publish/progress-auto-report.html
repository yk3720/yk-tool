自動化の4つのパーツ

報告自動化は、講義どおりトリガー / ソース元 / 処理する場所 / 届ける先の4つに分解して設計しました。

トリガー

GAS の時間トリガー（毎晩22時台）

Google Apps Script（GAS）のインストール可能な時間トリガーで毎日実行。nearMinute を使うと、指定分の前後約15分で起動します。

出典: ClockTriggerBuilder（Google Developers）
ソース元

Googleスプレッドシート

帰宅中にスマホから進捗を入力。列は業界標準に合わせて刷新（件名・状況・結果・特記事項など）。進捗率は完了数÷計画数をGASが計算します。

処理する場所

GAS（集計＋HtmlService）

データを一括読み込みし、サマリー生成とHTMLレポート公開までを同じスクリプトで実行。ウェブアプリとして公開した固定URLをLINEに載せます。

届ける先

LINE Messaging API（Push）

LINE Notify は2025年3月31日に終了済みのため、Messaging API の Push Message を採用。日本のコミュニケーションプランなら月200通まで無料で、1日1通運用なら十分です。

出典: LINE Notify 終了案内 出典: Messaging API の料金

工夫したポイント

動くものを作ったあとに見えた、進め方と設計の工夫です。発表で共有したい核はこの5点です。

1

「まず動かす」→「育てる」

最初から完璧を狙わず、テキストをLINEに送るだけから開始。動いたあとでHTMLレポート・ガント・列刷新を積み上げました。どこで詰まっても「前の動く状態」に戻れるのが精神的に効きました。
2

完成形のHTMLを先に作る

レポートの見た目（模範解答）を先に固めてからGASに流し込みました。AIに「何を作るか」を画面で示せると、実装中のブレが減ります。
3

LINEは2段構え（テキスト＋URL）

件数はチャットで即把握、詳細はブラウザのHTMLで確認。HTML全文をメッセージに載せないことで、スマホでも読みやすく、レポート更新も同じURLで追えます。
4

段階を分けて育てる（ガントは後回し）

ガントに必要な「開始予定日」列が最初は無かったため、まずテーブル動的生成を完成させ、列追加後にガントを実装。一気に全部やらず、前に進む単位を小さくしました。
5

「つなぎ目」と秘密情報の管理

公式アカウント作成・Messaging API・トークン・Webhook・GASデプロイなど、自動化＝つなぎ目作りだと実感。トークンはコード直書きせずスクリプトプロパティへ。アカウント類はパスワードマネージャで一元管理する方針にしました。
