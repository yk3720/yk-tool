POINT 2

ツールで解決する課題

図解が増えるほど、「何のための図解だっけ」が増える

タイトルやURLだけでは、当時の目的が思い出せないことがある。後から見返したときに手がかりになる一言メモを、自由に追記できるようにした。

Before
  • ·図解は見つかっても、目的が曖昧
  • ·メモを残す場所がない（または消える）
  • ·ブラウザを閉じると記憶も消える
After
  • ·詳細ペインで一言メモを追記できる
  • ·Neon に保存され、リロード後も残る
  • ·「探す」だけでなく「思い出す」ができる

POINT 3

工夫したポイント

1

保存先に Neon（Postgres）を選んだ

Vercel の Storage / Marketplace から追加でき、接続文字列（DATABASE_URL）がプロジェクトに入る。図解一覧＋メモのような「行と列」のデータに合い、課題の手順とも揃う。

出典: Neon × Vercel 連携ガイド · Neon Free プラン

2

メモを「見せる」だけでなく「残す」

詳細ペインで編集したメモを API 経由で Neon に書き込む。ページを開き直しても同じ内容が戻るので、画面が本当に記憶を持ったと言える。

PATCH でメモ更新 初回は表作成＋シード
3

接続が無いときはモックに切り替える

DATABASE_URL があるときだけ Neon を使い、無いときはメモリ上のモックで動かす。ローカル確認と本番永続化を同じ画面で切り替えられる。

POINT 4

苦戦したポイント

いちばん時間がかかったのは、Neon と Vercel の画面を行き来しながら「どこに何があるか」を掴むことでした。

連携画面の往来

Storage・環境変数・再デプロイ・Rotate など、操作場所が複数に分かれており、「いまどの画面で何を直しているか」がわかりにくい。迷子になると時間が溶ける。

接続情報とチャット履歴

自分ではチャットにパスワードを貼らなくても、AI がローカルの設定ファイルを読んでしまい、履歴に接続文字列が残ることがあった。あとから鍵を回し（Rotate）、エージェント側のルールも直した。

次に同じ作業をするときのメモ

  • ·図解管理用の Vercel プロジェクトに Neon を足す（別ツールの DB は流用しない）
  • ·接続文字列はチャットに貼らず、Rotate 後は再デプロイを忘れない
  • ·エージェントには .env の中身を読ませない
