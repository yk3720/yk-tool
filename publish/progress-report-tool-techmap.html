進捗報告自動化ツール GAS × Spreadsheet × LINE Messaging API

Google Apps Script Spreadsheet LINE Messaging API HtmlService 費用：完全無料

1. ひとことで言えば

帰宅中にスマホでスプレッドシートへ入力するだけで、毎晩自動でHTMLレポートが生成され、LINEに届くシステム。口頭説明・個別メール連絡を一切なくす。

対象読者

制御設計者（作成側）
メカ・電気設計者・生産担当（閲覧側）

カバーする範囲

トリガー / データ取得 / HTML生成 / LINE送信 の4パーツ

費用

Google側：無料
LINE側：月200通以内で無料

2. なぜ作るのか — 解決したい課題

現状の問題

  • 装置立ち上げ中はトラブルが多発するが、担当メカ設計者は別工場にいて直接話せない
  • スプレッドシートに手動で書いて連絡する作業が毎回発生し、非効率
  • 上長からの進捗確認に都度口頭で答える必要があり、対応時間がとられる

解決策のポイント

  • 入力は「帰宅中の電車」でスマホから。特別な作業時間は不要
  • 関係者は毎晩LINEを確認するだけ。個別連絡が不要になる
  • Google / LINEの無料機能で完結。新たなコストゼロ

3. まず理解する3つ

この3つを押さえれば、ツール全体の流れが見える。

1

GAS（Google Apps Script）は「Googleのサーバーで動くJavaScript」

GAS（Google Apps Script：グーグル アップス スクリプト）はGoogleのクラウド上で実行されるスクリプト実行環境。自分のPCを起動していなくても、Googleのサーバーがコードを動かしてくれる。SpreadsheetApp・HtmlService・UrlFetchApp など、Google製サービスをAPIとして呼び出せるのが最大の利点。

API（Application Programming Interface：アプリケーション プログラミング インタフェース） — ソフトウェア同士が機能を呼び合うための「接続口」。ここではGoogleサービスやLINEの機能をコードから呼び出す窓口を指す。
2

時間トリガーは「スマートプラグのタイマー機能」と同じ仕組み

GASのインストール可能トリガー（Installable Time-driven Trigger）は、毎晩22:30にGAS関数を自動実行する仕組み。スマートプラグの「21:00になったら電源ON」と同じ発想で、条件（時刻）に達したらコードが動く。エラー時はGmailへ自動通知が届く。

トリガー（Trigger） — 特定の条件が満たされたときにプログラムを自動起動する仕組み。ここでは「毎晩22:30」という時刻条件が引き金（トリガー）になる。
3

LINE送信は「GASからLINEのAPIを叩く」だけ

LINE Messaging API（LINE メッセージング API）は、プログラムからLINEのメッセージを送受信するための接続口。GASのUrlFetchApp.fetch()でLINEのサーバーにHTTPリクエストを送るだけで、自分のLINEにメッセージが届く。2025年3月に廃止されたLINE Notifyとは別物で、Messaging APIが現在の正式手段。

HTTP（HyperText Transfer Protocol：ハイパーテキスト転送プロトコル） — Webブラウザとサーバーがデータをやりとりするためのプロトコル（通信規約）。GASからLINEへのメッセージ送信も、このHTTPリクエスト/レスポンスの形式で行う。

4つのパーツ詳解

パーツ1：トリガー — 時間駆動で自動起動

GASのインストール可能トリガー（Installable Trigger）を使い、毎晩22:30頃に関数を自動実行する。一度設定すれば以降は完全自動。

このコードがやること：毎日22:30頃にsendDailyReport関数を自動実行するトリガーを登録する

ScriptApp.newTrigger("sendDailyReport")
  .timeBased()
  .atHour(22)
  .nearMinute(30)
  .inTimezone("Asia/Tokyo")
  .everyDays(1)
  .create();
重要： 22:30指定でも実際は22:30〜23:30の間のランダムなタイミングで実行される（GAS仕様）。厳密な時刻指定は不可能。
パーツ2：ソース元 — スプレッドシートから一括取得

SpreadsheetApp でスプレッドシートのデータを読み込む。カラム構成は以下の11項目（インデックス0〜10）。

[0] No [1] 登録日 [2] 期限 [3] 区分 [4] 装置名 [5] 内容 [6] 現在 [7] 総数 [8] 状態 [9] 優先度 [10] 進捗%
1 04/01 04/07 計画内 塗布装置 手動：供給部 3 16 対応完了 中 18.75%

このコードがやること：シート全体のデータを2次元配列として一括取得する（ベストプラクティス）

const sheet = SpreadsheetApp
  .openById("スプレッドシートのID")
  .getActiveSheet();
// 全データを一括取得（セル単位でのループは厳禁）
const data = sheet.getDataRange().getValues();
ベストプラクティス： セルを1つずつ読む実装は実行時間が爆発する（1万セルで70秒→1秒の差）。必ずgetDataRange().getValues()で一括取得する。
パーツ3：処理 — HtmlServiceでHTMLレポートを生成

GASのHtmlService（HTML サービス）でテンプレートHTMLにデータを流し込み、GASウェブアプリとして公開することで固定URLを得る。このURLをLINEで送る。

計画内作業 / 不具合対策 それぞれ一覧

重要： GASでは doGet() は予約済みの関数名。ウェブアプリへのHTTP GETリクエストが来たとき、GASが自動的にこの名前の関数を探して実行する。別の関数名にすると動かない。同様に、createTemplateFromFile('Report')の 'Report' はGASプロジェクト内に別途作成する Report.html ファイルを指す。

このコードがやること：doGet()でHTTPリクエストを受け取り、Report.htmlテンプレートにスプレッドシートデータを流し込んで返す

// Code.gs（GASプロジェクト内のメインスクリプト）
// doGet()はGASの予約関数名。ウェブアプリURLへのGETリクエストで自動実行される
function doGet() {
  const t = HtmlService.createTemplateFromFile('Report');
  // 'Report' = 同じGASプロジェクト内にある Report.html ファイルを指す
  t.data = SpreadsheetApp
    .openById("ID")
    .getActiveSheet()
    .getDataRange()
    .getValues();
  return t.evaluate();
}

// Report.html（GASプロジェクト内のHTMLファイル）
// <?= ?> はXSS対策の自動エスケープ付きで出力
<? for (var i = 0; i < data.length; i++) { ?>
  <td><?= data[i][5] ?></td>  // [5]は内容カラム（0始まりインデックス）
<? } ?>
XSS（Cross-Site Scripting：クロスサイトスクリプティング） — 悪意のあるHTMLやJavaScriptをコンテンツに埋め込む攻撃手法。<?= ?>はこれを防ぐ自動エスケープが入るため安全。
パーツ4：届ける先 — LINE Messaging API で送信

LINEはHTMLをそのまま送れないため、「テキストサマリー」と「レポートURL」の2段構えで送信する。GASのUrlFetchApp.fetch()でLINEサーバーにHTTPリクエストを送る。

たとえ話：郵便局の窓口
GAS = 差出人（手紙を書いて窓口に持ち込む）
LINEサーバー = 郵便局（配送インフラ）
userId = 宛先の住所（届け先の特定に必須）
チャネルアクセストークン = 差出人の身分証（なりすまし防止）
LINE_USER_ID の取得方法： LINE Developers Console で公式アカウントを友達追加後、Webhookイベントの event.source.userId から取得する。詳細は LINE公式ドキュメント（Getting user IDs） を参照。

このコードがやること：LINE APIへPOSTリクエストを送り、テキストとURLの2メッセージを自分のLINEに送信する

function sendLineMessage(summary, reportUrl) {
  // APIキーはコードに直書きせず、PropertiesServiceに保存
  const token = PropertiesService
    .getScriptProperties()
    .getProperty("LINE_TOKEN");
  const userId = PropertiesService
    .getScriptProperties()
    .getProperty("LINE_USER_ID");
  // LINE_USER_ID: LINE DevelopersでBotを友達追加後、Webhookイベントから取得

  UrlFetchApp.fetch("https://api.line.me/v2/bot/message/push", {
    method: "post",
    headers: {
      "Content-Type": "application/json",
      // "Bearer xxx" はHTTPベアラー認証の形式。LINEがこの形式でトークンを要求する
      "Authorization": `Bearer ${token}`
    },
    payload: JSON.stringify({
      to: userId,
      messages: [
        { type: "text", text: summary },    // 当日のサマリー
        { type: "text", text: reportUrl }   // HTMLレポートのURL
      ]
    })
  });
}
Bearer認証（HTTPベアラー認証） — Authorization: Bearer <トークン>の形式でアクセストークンをHTTPヘッダーに添える認証方式。LINE Messaging APIはこの形式を必須とする。

PropertiesService（プロパティ サービス） — GASでAPIキーやパスワードを安全に保管するサービス。環境変数に相当する仕組み。コードに直書きするとGitHub等への誤公開リスクがある。

3つのたとえ話で全体像を掴む

1

PLCのスケジュール実行 — トリガーは「PLC（Programmable Logic Controller：プログラマブルロジックコントローラ）のタイムスケジュール機能」と同じ発想。「22:30になったら実行」という条件をあらかじめ設定しておくだけで、その後は無人でスクリプトが起動する。

2

工場の一括発注 — SpreadsheetAppのデータ一括取得は「1個ずつ倉庫に取りに行く」のではなく「まとめてトラックで一括搬出する」ような効率化。APIコール1回でシート全体を2次元配列として取得する。

3

掲示板のURL連絡 — LINEへのレポート送信は「HTMLを全文メールで送る（大きな荷物を手渡し）」のではなく「GASウェブアプリとして公開したレポートのURLをLINEで通知する（掲示板の場所を伝える）」発想。レポートの更新も同じURLで反映される。

Simple TriggerとInstallable Triggerの違い

Simple Trigger（シンプルトリガー）

onOpen・onEditなど組み込みの関数名で自動発火。外部サービス（GmailApp・UrlFetchApp等）へのアクセス不可。

Installable Trigger（今回採用）

ScriptApp.newTrigger()で登録。外部APIへのアクセスが可能。時間指定による定期実行ができる。エラー時はGmailに通知が届く。

5. 初心者がはまりやすい落とし穴

LINE Notify は2025年3月に廃止済み

旧来の LINE Notify は2025年3月31日をもってサービス終了。「LINE Notify GAS」で調べると古い記事が多いが、そのまま使おうとしてもエラーになる。正しい手段は LINE Messaging API（Push Message）。LINE Developers Console でのアカウント作成が必要。

トリガーは「±30分」ズレる

GASの時間トリガーは指定時刻から最大1時間の幅でランダムに実行される（例：22:30指定 → 22:30〜23:30の間で実行）。「毎日ちょうど22:30に届く」は実現不可能。運用上の許容範囲を設けておくこと。

セルを1つずつ読むと実行時間上限に引っかかる

sheet.getRange(i, j).getValue()を ループで呼ぶと、毎回Googleサーバーとの通信が発生する。100行×11列で1,100回の通信となり、6分の実行時間上限を超えてタイムアウトすることがある。必ずgetDataRange().getValues()で一括取得する。

APIキーをコードに直書きしない

LINEのチャネルアクセストークンをソースコードに書くと、GASのコードを共有・公開したとき漏洩する。PropertiesService.getScriptProperties()に保存し、getProperty("KEY名")で参照する形にする。

GASウェブアプリの公開設定を忘れる

HtmlServiceで生成したレポートをLINEから開くには、GASウェブアプリとしてデプロイし、アクセス権を「全員（匿名ユーザーを含む）」に設定する必要がある。デフォルトでは自分のGoogleアカウントのみアクセス可能で、LINEからのアクセスはできない。操作手順：GASエディタ（スプレッドシート → 拡張機能 → Apps Script）の右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」→ アクセスできるユーザー「全員」に設定。

注意： デプロイのたびに新しいURLが生成される（バージョン管理）。コードを更新したら必ず「新しいデプロイ」ではなく「デプロイを管理」→「編集」でバージョンを更新することで同一URLを維持できる。

OAuth認証ダイアログで止まる（初回実行時）

GASスクリプトを初めて実行すると「このアプリはGoogleによって確認されていません」という警告ダイアログが出る。不審なアプリに見えるが、これは自分で書いたスクリプトに対してGoogleアカウントへのアクセス権限を付与する正常なOAuth認証フロー。「詳細」→「安全ではないページに移動」→「許可」の順にクリックして進む。

7. 専門用語集

GAS（Google Apps Script：グーグル アップス スクリプト）

Googleのクラウド上で動くJavaScript実行環境。Spreadsheet・Gmail・Driveなどとシームレスに連携できる。→ 関連：HtmlService、SpreadsheetApp

SpreadsheetApp

GASからGoogleスプレッドシートを操作するためのクラス。openById()でシートを開き、getDataRange().getValues()でデータを一括取得する。→ 関連：GAS、HtmlService

HtmlService（HTML サービス）

GASでHTMLページを生成・公開するためのサービス。createTemplateFromFile()でHTMLテンプレートにデータを流し込み、固定URLのウェブアプリとして公開できる。→ 関連：GAS、XSS

Installable Trigger（インストール可能トリガー）

GASで時刻・スプレッドシートのイベントなどを条件に関数を自動実行する仕組み。指定時刻から最大1時間のランダム幅がある点に注意。→ 関連：GAS、ScriptApp

LINE Messaging API（LINE メッセージング API）

プログラムからLINEメッセージを送受信するための公式API。2025年3月廃止のLINE Notifyの後継。Push Messageを使うとユーザーIDを指定して能動的にメッセージを送れる。→ 関連：Push Message、UrlFetchApp

Push Message（プッシュ メッセージ）

LINE Messaging APIの送信方式の一つ。ユーザーからのメッセージを待たず、ボット側から能動的にメッセージを送信できる。無料プランでは月200通が上限。→ 関連：LINE Messaging API

UrlFetchApp（URL フェッチ アップ）

GASから外部URLにHTTPリクエストを送るためのクラス。LINEへのメッセージ送信はこのクラスを通じてLINEサーバーのAPIエンドポイントにPOSTリクエストを送る形で実現する。→ 関連：GAS、HTTP

PropertiesService（プロパティ サービス）

GASでAPIキーやパスワードなどの秘密情報を安全に保管するサービス。コードに直書きするのは危険であり、このサービスを使って環境変数的に管理する。→ 関連：GAS、LINE Messaging API

XSS（Cross-Site Scripting：クロスサイトスクリプティング）

悪意のあるスクリプトをWebページに埋め込む攻撃。HtmlServiceの<?= ?>プリントスクリプトレットはHTMLを自動エスケープしてXSSを防ぐ。→ 関連：HtmlService

Flex Message（フレックス メッセージ）

LINE Messaging APIのリッチメッセージ形式。カード・ボタン・グリッドなど複雑なレイアウトをJSON定義で表現できる。今回はテキスト+URLで十分だが、発展的活用として検討できる。→ 関連：LINE Messaging API

8. 次に学ぶと良いもの

LINE Flex Message

LINEのメッセージをカード型・グリッド型にリッチ化できる。ガントチャートのサマリーをテキストではなく視覚的なカードで送れるようになる。

Chart.js / D3.js

生成するHTMLレポートに動的なガントチャートや進捗グラフを描画するJavaScriptライブラリ。現在のCSS実装よりも柔軟で表現力が高い。

GAS clasp（コマンドラインツール）

GASのコードをローカルでTypeScriptとして開発し、GitでバージョN管理できるCLIツール。本格開発に移行する際に必須の知識。

Google Cloud Secret Manager

PropertiesServiceより高セキュリティな秘密情報管理サービス。複数のGASプロジェクトで共通のAPIキーを管理したい場合に有効。

GmailApp（メール送信の代替）

HTMLレポートをLINEではなくメールで配信する場合の代替手段。GASのGmailApp.sendEmail()でHTML形式のメールを送信できる。

LINE Webhook（双方向通信）

LINEユーザーからのメッセージを受け取り、ボットが応答できるようにする仕組み。「進捗を聞けば即答するボット」へと発展させる際に必要。
